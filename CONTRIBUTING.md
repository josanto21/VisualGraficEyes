# Cómo contribuir a VisualGraficEyes (VGE)

Gracias por tu interés. VGE es un prototipo en desarrollo y toda ayuda cuenta: una idea, un error encontrado, una mejor explicación o un ejemplo nuevo.

No necesitas saber programar para aportar. Mucho del trabajo pendiente es documentación y prueba con personas reales.

## Antes de empezar

1. Lee el [README](README.md) para entender qué es VGE y qué está comprobado.
2. Revisa los [Issues abiertos](https://github.com/josanto21/VisualGraficEyes/issues) por si alguien ya propuso lo mismo.
3. Si vas a tocar código, sigue la sección **«Desarrollar»** del README para instalar y correr las pruebas.

## 1. Proponer ideas o mejoras

Abre un **Issue** nuevo con:

- **Título** corto y claro. Ejemplo: «Agregar un ejemplo del ciclo del agua en modo Mapa».
- **Necesidad:** qué falta o qué podría explicarse mejor.
- **Propuesta:** qué harías y para quién sería útil.
- **Resultado esperado:** cómo sabremos que la mejora está lista.

## 2. Reportar errores

Abre un **Issue** e incluye:

- Qué hiciste (pasos para repetir el problema).
- Qué esperabas que pasara y qué pasó en realidad.
- Navegador, sistema operativo y, si aplica, el asistente de IA que usaste.
- Una captura de pantalla si ayuda a entenderlo.

No publiques contraseñas, claves de API ni datos personales en los Issues.

## 3. Contribuir con documentación o recursos

Son bienvenidos:

- Correcciones de redacción, ortografía o enlaces rotos.
- Guías para principiantes y traducciones.
- Ejemplos nuevos de los siete modos: anatomía, laboratorio, escena 3D, pasos, video, mapa y datos.

Si agregas imágenes, modelos 3D, fuentes o videos de terceros, indica **autor, enlace y licencia**. Si no puedes confirmar la licencia, no lo subas.

Si usaste IA para crear el aporte, dilo en el Pull Request y revisa que no invente funciones, cifras ni resultados.

## 4. Solicitar la incorporación de cambios (Pull Request)

1. Haz un **fork** del repositorio (o crea una rama si tienes acceso).
2. Crea una rama con un nombre descriptivo, por ejemplo `docs/guia-siete-modos`.
3. Haz tus cambios en pasos pequeños, con commits claros.
4. Si cambiaste código, corre las pruebas (`npm test`) y confirma que pasan.
5. Abre un **Pull Request** hacia `main` y explica:
   - qué cambiaste y por qué;
   - qué Issue resuelve (escribe `Closes #número`);
   - cómo lo comprobaste y qué quedó **sin verificar**.
6. El autor revisará el PR. Puede pedirte ajustes antes de integrarlo.

## Convenciones

- Idioma: español, con lenguaje sencillo.
- Una mejora por Pull Request.
- Marca como **«No verificado»** cualquier afirmación que no hayas comprobado.

## Contacto

Para dudas, abre un Issue con la etiqueta `pregunta` o menciona a [@josanto21](https://github.com/josanto21).
