# Rigor por materia

Usar esta referencia para evitar que el atractivo visual sustituya al modelo correcto. Aplicar solamente los controles pertinentes.

## Electrónica y señales

- Identificar topología, componentes, fuentes, unidades y supuestos.
- En un circuito resistivo básico, comprobar ley de Ohm, potencia y leyes de Kirchhoff según corresponda.
- Para una señal, conectar amplitud, frecuencia, periodo y fase con la misma función temporal que produce la gráfica.
- Distinguir valor instantáneo, pico, pico a pico y RMS. Utilizar RMS = pico / raíz de 2 solo para una sinusoidal sin componente continua.
- Limitar controles al dominio válido. Manejar divisiones por cero y valores imposibles con un estado explícito.
- Distinguir fallos físicos de límites de un modelo ideal. No inventar humo, destrucción o comportamientos de componentes sin un modelo que los justifique.
- Usar un simulador adecuado si el comportamiento requiere transitorios, modelos semiconductores o interacción compleja.

## Física y mecanismos

- Mantener consistencia dimensional, condiciones iniciales, magnitudes conservadas y signos.
- Relacionar posición, velocidad, fuerza, flujo o energía cuando el tema lo requiera.
- Si se usa una ley idealizada, decir qué se aproxima: rozamiento, rigidez, pérdidas, compresibilidad u otros supuestos.
- Mantener geometría, uniones y movimiento compatibles. Una pieza no debe atravesar otra salvo que la escena indique corte o separación.
- No presentar un modelo visual con movimiento arbitrario como motor físico validado.

## Matemática

- Indicar dominio y restricciones pertinentes.
- Mantener equivalencia entre pasos; señalar si una operación exige condiciones adicionales.
- Distinguir una demostración de un ejemplo numérico o intuición gráfica.
- Respetar escalas y límites al explorar funciones; no ocultar singularidades ni trazar conexiones a través de discontinuidades.
- Al resolver sistemas, comprobar cada ecuación. Al proponer un resultado, verificarlo por un método sencillo e independiente cuando sea posible.
- Mostrar la correspondencia entre metáfora y símbolos sin mezclar unidades ni entidades.

## Algoritmos, programación y redes

- Mantener estado, entradas, salidas y orden de operaciones consistentes.
- Sincronizar cada paso visual con los datos y el código que representa.
- Identificar casos límite relevantes: entrada vacía, límites de índice, empate, error o saturación.
- Distinguir el modelo didáctico de la implementación exacta de una plataforma.
- Para redes, respetar capas, direcciones, encapsulación y funciones de protocolos. No equiparar una animación de paquetes con una captura real.
- Comprobar documentación oficial si se describen APIs, herramientas o comportamientos actuales.

## Biología, anatomía y sistemas orgánicos

- Usar fuentes pertinentes para estructuras, relaciones espaciales y funciones.
- Rotular cortes y esquemas simplificados. Señalar si tamaño, color o movimiento son ilustrativos.
- Distinguir función normal, variación y patología cuando el tema las incluya.
- No utilizar una ilustración educativa para inferir un diagnóstico personal.
- Conservar terminología y correspondencias entre estructura y función.

## Datos, comparaciones e historia

- Mantener fuente, fecha, población o ámbito y unidades de los datos.
- Distinguir medición, estimación, proyección y datos simulados.
- Identificar porcentajes, denominadores, valores ausentes y periodos comparables.
- Evitar escalas que creen diferencias engañosas; justificar recortes o escalas no lineales.
- Separar correlación, causalidad y secuencia temporal.
- Para mapas o cronologías, distinguir hechos verificados de interpretaciones y marcar incertidumbre pertinente.

## Exactitud transversal

- Etiquetar las analogías como analogías y señalar dónde dejan de corresponder.
- Mantener una única fuente de estado para valores, geometría y animación.
- Citar afirmaciones externas cuando se hayan investigado. No inventar fuentes ni precisión.
- Revisar al menos un estado ordinario y un límite relevante si existen controles.
- Informar solo de verificaciones realizadas: estructura revisada, cálculo comprobado, interacción observada o renderizado inspeccionado.
